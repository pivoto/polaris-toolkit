# usage 生成工具类使用文档

为目标 Java 类生成结构化 markdown 使用文档，覆盖功能概述、类级信息、逐方法说明（签名 / 参数 / 返回值 / 异常 / 示例）与注意事项，写入指定目录下的 `<类名>.md`。

## 语言约定

- 文档正文一律中文；仅类名、方法名、标识符、代码、文件路径、Maven 坐标保持原样。
- 代码示例中的注释用中文。
- 标识符（类名、方法名、变量名、包名）不翻译，按现有命名规范保留英文。

## 参数解析

args 形如：`<目标类> [输出目录] [--no-overwrite]`

- **目标类**（必填）：可为简单类名（如 `Strings`）、全限定类名（如 `io.polaris.core.string.Strings`）或源文件相对/绝对路径。
- **输出目录**（可选，默认 `docs/usage/<模块名>`）：生成的 `<类名>.md` 写入此目录。目录不存在时自动创建。
- **`--no-overwrite`**（可选）：目标文件已存在时不覆盖，改为写入 `<类名>.<时间戳>.md`。

若 args 为空：用 `AskUserQuestion` 询问"目标类"与"输出目录"后再继续，不要自行假设。

## 工作流程

### 1. 定位源文件

按优先级用 Glob 定位（pattern 用 `**/<类名>.java`，简单类名直接用；全限定名按包路径将`.`转为`/`：

命中多个时，列出全部候选路径请用户选择；无命中时告知用户并停止，不要臆造路径。

### 2. 读取并分析类

用 Read 读取源文件，提取类与方法的详细信息：

- **类级信息**
  - `package` 与完整类名。
  - 类声明：`class` / `interface` / `enum`、是否 `final` / `abstract` / `static` 嵌套类。
  - 稳定性注解：`@Published`、`@Internal`、`@Compatible`、`@Legacy`、`@Experimental`、`@Uncompleted`、`@Warning` 等——如实记录。
  - 类级 Javadoc 概要（若有）。
  - 是否工具类形态：构造私有 + 全静态方法。
  - 线程安全性：查找类/字段上的 `@ThreadSafe` / `@NotThreadSafe`，或 Javadoc / 字段 `final` / 无可变状态等线索得出结论；无明确依据时写"源码未显式声明，需调用方自行保证"而非杜撰。
- **公共方法清单**
  - 覆盖所有 `public` 方法；若类非 `final` 且设计为可继承，则同时覆盖 `protected` 方法。
  - 跳过：`private`、包级、`Object` 继承来的覆盖（如 `toString`/`equals` 除非是工具类核心语义）、`@Internal` 标注的内部方法（在文档中注明存在但简略带过）。
  - 每个方法记录：完整签名（含泛型）、Javadoc、参数列表、返回类型、`throws` 声明、方法体关键逻辑摘要。
- **重载分组**
  - 对"纯委托且语义一致"的重载（如 `truncateUtf8` / `truncateGbk` / `truncateGb18030` 都委托给 `truncate(String,int,Charset)`）归并到主方法下，以"重载"小节列一张表简述各变体差异。
  - 签名差异显著或有独立语义的重载单独成节。
- **依赖与前置条件**
  - 扫描 `import` 与字段，识别典型用法所需的前置条件（如需 SPI 注册、需引入额外模块依赖、需特定初始化）。

必要时用 Grep 补充：查找类 Javadoc、相关常量类（`*Consts`/`*Keys`）、被调用的关键方法语义，以避免对参数含义的猜测。

### 3. 生成文档

按下文"文档模板"生成 markdown，用 Write 写入 `<输出目录>/<类名>.md`，要求如下：

1. 文件命名
   - 文件名取**简单类名** + `.md`（如 `Strings.md`），不取全限定名。
   - 输出目录不存在时，先用 Write 写文件即可（Write 会自动创建父目录）。
2. 文档标题和概述
   - 使用清晰的标题描述工具类名称和用途
   - 提供简短的概述，说明该工具类的主要功能和适用场景
3. 类级信息
   - 工具类的完整类名和包路径
   - 主要职责和设计目的
   - 线程安全性说明（如果适用）
4. 方法功能描述
   对每个公共方法分别描述：
   - 方法基本信息
     - 方法签名（包括泛型参数）
     - 简洁的功能说明
     - 参数详细解释（名称、类型、含义、是否可为空）
     - 返回值说明（类型和含义）
     - 异常情况说明（抛出的异常类型和条件）
   - 使用示例
     - 提供典型的使用代码示例
     - 展示常见使用场景
     - 包含必要的导入语句
     - 注释说明关键步骤
5. 注意事项和最佳实践
   - 性能相关提示
   - 内存使用考虑
   - 并发使用限制
   - 常见误用情况
   - 版本兼容性说明
6. Markdown格式要求
   - 使用适当层级的标题组织内容
   - 代码块使用`java`标记
7. 示例代码规范
   - 保持代码简洁易懂
   - 包含必要的上下文
   - 使用有意义的变量名
   - 添加适当注释说明


### 4. 反馈结果

生成完成后输出：

- 生成文件的绝对路径；
- 新建 / 覆盖 / 改名（`--no-overwrite` 命中时）情况；
- 实际描述的公共方法数量，以及被跳过的方法及原因（如内部方法、纯委托重载归并数）；
- 若有源码未体现、需用户补充确认的点（如线程安全未声明），单独列出提示。

## 注意事项

- **只写公共 API**：私有 / 包级方法不写；`@Internal` 标注的方法在文档中注明"框架内部使用，不保证稳定"并简略带过，不展开示例。
- **示例必须可编译**：导入语句完整、变量名有意义、关键步骤加中文注释。优先使用项目真实可用的类型与常量，不要杜撰不存在的 API。
- **不臆造语义**：源码未体现的异常、线程安全、性能数字一律不写；不确定处用"以源码为准"或留 `{{待确认}}` 占位提示用户补充，绝不编造。
- **稳定性注解驱动提示**：在"版本兼容性"中据实标注，并将其影响纳入"常见误用"（如 `@Legacy` 类应提示用户迁移）。
- **大类处理**：公共方法 > 25 个时，在"方法说明"下按职责分组设二级标题（如 `## 字符串截断`、`## 填充与对齐`），每个方法仍在对应分组下单独成节，避免一长串平铺。
- **重载归并范围**：仅对"纯委托且语义一致"的重载归并；签名差异显著或有独立语义的（如额外参数改变行为）单独成节。
- **与既有文档不冲突**：本 skill 生成的是单类使用手册，面向 `docs/usage/`；不修改 `docs/` 下既有的按主题组织的文档。
